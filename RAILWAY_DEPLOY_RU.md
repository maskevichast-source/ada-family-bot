# Обновление существующего GitHub → Railway проекта

## 1. Перед обновлением
1. Сделайте резервную копию рабочей Google-таблицы и сохраните текущий commit.
2. Завершите ожидающие комментария чеки/категории в старом боте: его старые
   RAM-очереди невозможно перенести автоматически.
3. Если нужна старая история, сохраните `chat_history.json` из старого deployment.
   Уже утраченные сообщения восстановить из удалённого диска невозможно.
4. Посмотрите старые pending-напоминания: просроченные будут отправлены после старта.
   В снимке REM_20260905_093342_094647 про Салтанат адресовано Владу.
   Если имелась в виду Диана, исправьте target_user вручную — код не угадывает прошлое.

Не заменяйте более свежую Google-таблицу присланным XLSX.

## 2. Постоянный диск
В существующем Railway service создайте/подключите **Volume** с mount path:
```
/app/data
```
Variables:
```
ADA_STATE_DIR=/app/data
CHAT_HISTORY_FILE=/app/data/chat_history.json
```
В Volume: SQLite-черновики/чеки, история последних 50 сообщений, отметки рассылок
и lock процесса. Одних Variables недостаточно: сам Volume подключается в Railway.
Не удаляйте его при redeploy. Если сохранили старый history JSON, перенесите его
в `/app/data/chat_history.json` ДО запуска.

## 3. Railway Variables
Существующие секреты остаются в Railway. Проверьте:
- TELEGRAM_BOT_TOKEN
- OPENAI_API_KEY
- DEEPSEEK_API_KEY
- GOOGLE_SHEETS_KEY — ID рабочей таблицы из URL
- GOOGLE_CREDENTIALS_JSON — полный JSON сервисного аккаунта
- VLAD_TELEGRAM_ID, DIANA_TELEGRAM_ID — разные положительные ID
- FAMILY_CHAT_ID — ID семейной группы, обычно отрицательный
- ADA_STATE_DIR, CHAT_HISTORY_FILE — как выше

Google-таблица должна быть открыта `client_email` сервисного аккаунта на редактирование.
Переносы внутри private_key остаются экранированными `\n`.
Альтернатива JSON-переменной — доступный контейнеру файл CREDENTIALS_FILE.
Ключи, `.env`, credentials.json и Volume/data не коммитить.

Дополнительные настройки:
```
AUTO_GENERATE_LIMITS=true
SHEETS_READ_CACHE_SECONDS=10
LOG_LEVEL=INFO
```
Автолимиты сохранены и включены по умолчанию, как в исходном ZIP.
Для сознательного отключения — AUTO_GENERATE_LIMITS=false.
Read-cache можно выключить значением 0 для диагностики.

## 4. Обновите GitHub
Распакуйте ZIP и замените файлы в **корне существующего репозитория**.
Рядом должны лежать main.py, run.py, Dockerfile, railway.json, requirements.txt,
папки handlers/ и services/. Не добавляйте лишнюю внешнюю папку.

Проверьте diff, сделайте commit/push в подключённую к Railway ветку.
Старый worker остановите до включения нового — не должно быть двух polling-процессов.
GitHub-репозиторий и Railway service остаются прежними; новый сервер не нужен.

## 5. Railway settings
- Builder: Dockerfile. Файл: Dockerfile.
- Start Command: `python run.py`.
- Root Directory: каталог с Dockerfile, обычно корень `/`.
- **Одна replica.** Без второй копии с тем же Telegram-токеном.
- Volume: `/app/data`.
- HTTP healthcheck выключить: это worker, HTTP-порта у бота нет.
- Public domain не нужен.
- Проверьте старые UI overrides: они не должны противоречить railway.json.

Конфиг в ZIP задаёт Dockerfile/start command/одну replica.
Полная установка зависимостей и сборка здесь не выполнялись: смотрите build logs.

На старте проверяются переменные и схема; добавляются недостающие поля/листы;
сохраняются обслуживание Dim_Categories и санация алиасов; запускаются семь циклов.
Webhook снимается с drop_pending_updates=False — накопленные updates не сбрасываются.

Ожидаемая запись:
```
Ada ready: polling, group reminders, 7 background workers
```
Для проверки настроек/схемы без polling (в окружении с Variables):
```
python -m services.preflight
```

## 6. Доступ Telegram
Бот должен состоять в FAMILY_CHAT_ID и иметь право отправлять сообщения/файлы.
Для обычной речи в группе проверьте privacy mode в BotFather `/setprivacy`
или подходящие администраторские права бота. `/chatid` помогает сверить ID.
Доступ разрешён только ID Влада/Дианы, а не совпадению имени профиля.

**Личный /start не нужен для групповых напоминаний.**
Упоминания адресатов не гарантируют звуковой/push-сигнал: это зависит от Telegram
и настроек уведомлений участников.

## 7. Контрольный запуск
Лучше сначала использовать копию Google-таблицы:
1. `/start`, `/help`, `/debug`.
2. `Наопмни Диане через 2 минуты тест Дианы` — сообщение в группе, адресат Диана.
3. `Напомни нам обоим через 2 минуты общий тест` — одно сообщение в группе, два адресата.
4. Ежедневное напоминание → проверить recurrence и новую дату после отправки.
5. `/reminders` → удаление одного ID → `Нет`, затем повторить с `Да`.
6. Дать 10000 в долг → `Да`; возврат 2500 → `Да`: остаток 7500.
   Попытка вернуть 8000 отклоняется, Transactions не меняется от principal.
7. Взять 5000 → `Да`; вернуть 1000 → `Да`: остаток 4000.
8. Трата текстом и голосом; фото/PDF; комментарий к чеку только от автора.
9. Обычная беседа при ожидающем чеке; restart с черновиком и продолжение.
10. Правка банка, разделение суммы, удаление по ключевым словам.
11. Покупки, поездка с notes, рассрочка/Kaspi Red, подписки.
12. Погода, `/chart`, `/trend`, `/leaks`, `/report`, `/export`.
13. После redeploy проверить память и логи API/таблицы.

Тестовые команды пишут настоящие строки. Используйте тестовую таблицу
или затем удалите только тестовые записи по точным ID.

## 8. Ограничения и откат
- Живые API, права, ключи, квоты, сеть и реальные ответы моделей проверяются на Railway.
- Один worker; файловый lock не защищает разные серверы/разные Volume.
- При аварии между успешной отправкой Telegram и отметкой Sheets возможен повтор.
  Exactly-once между двумя внешними сервисами не гарантируется.
- Не правьте строки вручную одновременно с ботом: сторонние редакторы не участвуют в lock.
- Простой во всё окно погоды/дайджеста может пропустить эту рассылку.
- Перед откатом остановите worker, сохраните актуальные таблицу и Volume.
  Старый код не умеет новые Debts/черновики. Не откатывайте всю старую таблицу
  поверх новых операций и не удаляйте служебные колонки с данными.
