# Точечный патч: ввод документов/валюты и перенос напоминаний

## Для какой версии
Для предыдущего `ada_railway_group_release.zip`, выданного в этой переписке:
GitHub → Railway, команда `python run.py`, модули services/state.py и services/reminders.py.

**Это НЕ полный бот и НЕ патч к самому первому ada-family-bot-main.zip.**
В текущем доступном наборе файлов есть первоначальный архив, но нет выгрузки
живого коммита GitHub. Поэтому патч сохраняет остальные файлы и проверяет
интерфейсы предыдущей Railway-сборки до запуска polling.
Если код репозитория после неё менялся, нужны его актуальная копия и логи для
проверки полной совместимости. Проверка интерфейсов не заменяет интеграционный тест.

Новый run.py подключает узкие перехваты к имеющимся обработчикам до их регистрации.

В архиве файлы лежат по нужным относительным путям. Внешнюю папку

## 2. Перед заменой

- Остановите старый worker перед переключением; не запускайте две replica.

  Сам Railway Volume также должен быть подключён; одних Variables недостаточно.
- Токены/credentials.json/.env в GitHub не добавлять.

## 3. Деплой
Commit/push в подключённую к существующему Railway service ветку.
В Railway Start Command должна остаться именно:
```
python run.py
```
Запуск `python main.py` обходит подключение этого патча!
Dockerfile предыдущей сборки уже содержит ffmpeg и необходимые зависимости.
requirements не меняется. HEIC/AVIF зависит от доступного декодера; при его отсутствии
бот просит JPG/PNG или отправку как фото, а не падает.

Одна replica, HTTP healthcheck для worker не включать.
После рестарта найдите в логах:
```
ADA_INPUT_HOTFIX_READY
```
Если её нет или написано «Hotfix рассчитан на предыдущий ...» — патч не подключён/
версия не совпала. Не тестируйте запись денег до исправления запуска.

## 4. Что изменится

### Перенос напоминания
`Измени время напоминания про посылки с Китая на 11:00`
→ предпросмотр старого и нового времени → `Да`.
Изменяется существующий ID, новая строка не создаётся.
Если дата не указана, сохраняется дата исходного напоминания, не выбирается новый день.
`Завтра в 11:00` после уточнения продолжает правку, а не создаёт новую задачу.
Несколько совпадений → выбор ID. Старые дубли не удаляются автоматически.
`Напомни завтра ...` без времени теперь вызывает вопрос, а не выдуманное 21:00.
Групповая доставка предыдущей версии не меняется.

### Скрин OpenAI 11,60 $
Это USD, не KZT. Документ не попадает в обычное автосохранение.
Ада спрашивает фактическое списание в KZT, например:
```
списали 5860 KZT
```
Число выше — пример, используйте сумму из вашего банка, НЕ из инструкции.
Альтернатива — известный вам курс:
```
курс USD 505
```
Он означает KZT за 1 USD. Это не актуальный курс, а пример ввода.
Потом Ада показывает итог и ждёт `Да`.
Оригинал в USD и способ пересчёта остаются в комментарии операции.
При нескольких позициях одной валюты фактический общий итог распределяется
пропорционально с сохранением копеек; это явно отмечено в комментарии.
Несколько валют: `списали 5860 KZT за USD`, затем сумма для следующей валюты.
Неизвестная валюта: `валюта USD` или `валюта KZT` по фактическому документу.
Простая смена ярлыка уже известного USD на KZT запрещена.

### Ввод
- Текст и голос идут через прежний обработчик, но валютные суммы перехватываются до записи.
- Несколько операций из текста не обрезаются до первой, если модель вернула список.
- Фото Telegram и изображения, отправленные документом, читаются по содержимому,
  а не только по расширению.
- PDF/TIFF читаются постранично; банк/чек/выписка/возврат передаются модели с правилами
  итога, валюты и направления. Точность распознавания зависит от читаемости и модели.
- Голосовые и аудиофайлы нормализуются ffmpeg; аудио, отправленное документом, также поддержано.
- Все НОВЫЕ документы проходят предпросмотр и подтверждение `Да`, даже с подписью.
  Это сознательное изменение для защиты от ошибок OCR.
- `комментарий: ...` дополняет черновик; `Нет`/`Отмена` отменяет его.
- Неподтверждённая/ошибочная оплата не записывается без отдельного подтверждения факта.
- Известный идентичный сохранённый файл требует `это новая операция` и затем `Да`,
  если это действительно другая оплата.
- Обычный разговор и фраза «Да блять» не являются командой повторной записи.

### Незавершённые документы
`/receipts` — список ВАШИХ черновиков.
`документ DOC_...` или `документ LEGACY_...` — выбрать конкретный черновик.
При потере ответа Sheets: `повтори сохранение` — сначала проверяются ID,
затем дописываются отсутствующие строки.
Не отправляйте одно и то же фото многократно после сетевого таймаута.

Старые валютные/повреждённые очереди сначала копируются в отдельные черновики,
только после успешной копии отключаются от старого автосохранения.
Корректные старые KZT-очереди продолжают работать прежним способом.
Новые неподтверждённые/валютные документы сами через 20 минут не записываются.

## 5. Уже созданные дубли на скриншоте
Патч не имеет доступа к вашей таблице и не удаляет их задним числом.
Вызовите `/reminders`, проверьте записи про посылки.
На скрине старая строка на 21:00 — `REM_-5349521972_1171_0`,
новая на 11:00 — `REM_-5349521972_1179_0`.
Если в текущем списке старый ID всё ещё относится именно к лишнему напоминанию:
```
Удали напоминание REM_-5349521972_1171_0
```
Проверьте предпросмотр и подтвердите. Нужное на 11:00 не удалять.
Если ID уже изменились, используйте текущий список, а не пример.

## 6. Приёмка после деплоя
Лучше на тестовой Google-таблице:
1. Создать одно напоминание, перенести его, подтвердить: тот же ID и одна строка.
2. Ввести новую задачу без времени: должен быть вопрос, не 21:00.
3. Отправить скрин 11,60 USD: уточнение KZT, ни одной записи до подтверждения.
4. Ответить обычной фразой: нет зацикленного сохранения/общей ошибки.
5. Указать реальную сумму KZT, подтвердить: одна корректная запись с оригиналом в комментарии.
6. Текст, голос, JPG/PNG как фото и как документ, PDF с несколькими страницами, аудиофайл.
7. Перезапустить с ожидающим валютным документом: `/receipts` должен его сохранить.
8. Проверить логи и прежние команды/долги/отчёты; их файлы не заменялись.

## 7. Реальные ограничения
Проверены 70 локальных тестов целевой логики. Сервисы Google/Telegram/ИИ имитировались;
полная текущая Railway-сборка и живые API здесь не проверялись.
Не гарантируется распознавание любого размытого/обрезанного/зашифрованного документа.
Лимиты патча: 20 МБ, 20 страниц PDF/TIFF, 30 минут аудио.
Ответ OCR, обрезанный по токенам, НЕ записывается частично: нужно разделить документ.
HEIC/AVIF без декодера и анимированные изображения требуют обычного фото/статичного кадра.
Курс валют автоматически из интернета не берётся и не выдумывается.
Между Sheets и сетью нет гарантии exactly-once; проверка ID уменьшает риск,
но параллельные worker/ручные записи всё равно запрещены.
Если снова будет ошибка, нужны строки Railway около HF_OCR_FAILED,
HF_AUDIO_FAILED, HF_DOCUMENT_FAILED или HF_SHEETS_WRITE_UNCERTAIN без секретов.
