# Аудит релиза: Railway и групповые напоминания

## Результат и границы проверки
134 локальных тестовых случая прошли, Python-файлы компилируются.
Проверены бизнес-логика, обработчики и циклы с имитацией Sheets/Telegram/ИИ.
Графики, Excel и двухстраничный PDF создавались реальными установленными библиотеками,
многостраничный PDF рендерился локально. PDF и дашборд проверены визуально на снимке таблицы.
Обе страницы A4 без выходящих за страницу текстовых блоков.

**Живые API, установка полного requirements, Docker build и Railway deployment
здесь не выполнялись.** Клиентов Telegram/Google/OpenAI/DeepSeek/curl_cffi в среде нет:
в тестах используются import-shim, вместо API — имитация.
Тесты моделей используют заданные JSON-ответы, не доказывают качество реального LLM.
Python тестирования 3.13.5; целевой Docker/CI 3.11.
Живая приёмка и настройки — RAILWAY_DEPLOY_RU.md.

## Что найдено в исходном снимке

- Влад: 66 операций; Диана: 40.
- Расходы 957897,89 KZT; доходы 184400 KZT.
- Повторяющихся transaction_id, нулевых/отрицательных сумм не найдено.
- 9 сумм хранятся текстом. Чтение исправлено, новые суммы пишутся числами;
  исторические суммы без разрешения не перезаписаны.
- Три активных напоминания; «Владислав и Диана» нормализуется в «Семья».
- Напоминание про Салтанат записано для Влада. Из текста нельзя уверенно восстановить
  желаемого адресата; автоматического переназначения Диане не было.
- Справочник Power BI и пользовательские лимиты имеют разные значения;
  новый старт не заменяет пользовательские default_limit дефолтами.
- Рабочая Google-таблица в этой сессии не изменялась.

## Напоминания: предыдущая трактовка отменена
Все отправки направляются в FAMILY_CHAT_ID.
target_user — адресат в тексте и tg://user?id-упоминании.
«Семья/нам обоим» = одно групповое сообщение, два адресата.
Личный /start для такой доставки не нужен.
Содержимое задачи экранируется для HTML; настройка уведомлений остаётся на стороне Telegram.

Сохранены разовые/daily/monthly, дополнительно weekly.
Исправлены короткие месяцы, возврат к исходному числу, пропущенные повторения,
точки в часах, опечатка «наопмни», продолжение диалога при уточнении времени.
Понятные простые команды — локально; сложные/контекстные через ИИ, с проверкой
адресата/будущих дат и подтверждением интерпретации.
Удаление по ID/словам/контексту показывает точную подборку до смены статуса.
Ошибка отправки оставляет pending; отметка group:<chat_id> после успеха.

## Основные дополнительные исправления
### Диалог
- Локальные ответы тоже попадают в историю: контекст не рвётся после напоминания/долга.
- Railway Volume сохраняет историю/черновики; эфемерный JSON сам по себе не защищает от redeploy.
- Полный сегодняшний список, даже если операций более 200; архив до 200 с ID.
- Сохранены тон Ады, женское лицо, расписание семьи, банки/категории/Need-Want.
- Добавлены долги, ответ на сообщение, текущие авторские черновики.
- Недоступный источник отличается от пустого; один сбой не обязан ломать обычный разговор.
- Убрана жёсткая установка текущего года в 2026.
- Дополнены отсутствовавшие схемы JSON и обработчики split/get_weather/бытовых запросов.
- «Я должен работать», «вернул товар» и обсуждение долгов не перехватываются автоматически.
- Следующая реплика при ожидающем чеке больше не становится комментарием без разбора контекста.

### Учёт
- Исправлен разбор разделителей/дробей/знака и числовой тип новых сумм.
- Нулевые/отрицательные суммы и неизвестные типы не подтверждаются как сохранённые.
- Идемпотентные ID финансовых записей, долговых событий, планов напоминаний и подписных платежей.
- Split одним atomic batch вместо удаления оригинала и двух независимых вставок.
- Поиск по ключевым словам от новых к старым сохранён, но запись подтверждается по её ID.
- Согласование bank/source, наличные/карта, категории/подкатегории.
- Новая покупка «с карты Kaspi» не изменяет банк предыдущей.
- Нет молчаливого сложения долларов и тенге; KZT без автоматической конвертации.
- Пустой поиск/пустое вычёркивание не удаляет всё и не выдаётся за успешное действие.
- RAW для свободного текста в Sheets, строковый тип формул-подобных строк в Excel.

### Очереди и медиа
- Чеки и категории разделены по chat_id:user_id.
- Несколько чеков не перетираются; одинаковый message_id не удваивает очередь.
- Весь чек, включая подписанный, сохраняется в durable queue до первой записи:
  сетевой сбой не теряет оставшиеся позиции.
- Уточнённые комментарии/категории сохраняются до записи.
- Устаревшая кнопка не подтверждает новый вопрос.
- Новый вопрос категории не уничтожает старый: он сохраняется с уведомлением.
- PDF до 12 страниц читается целиком, больше — явная просьба разделить, не молчаливая первая страница.
- Обрезанный ответ Vision выявляется; размеры/типы файлов ограничены.
- Голос идёт в тот же pipeline; клиенты Voice/Vision закрываются после работы.

### Фон и таблица
- Power BI-справочник обновляется добавочно; санация алиасов пакетная.
- Проверка заголовков до рабочих задач; не всякий HTTP-сбой означает «лист отсутствует».
- Подписки 29–31 числа, пропущенная пятая минута и идемпотентность месячного платежа.
- Добавление подписки не помечает её оплаченной без явного указания.
- Предупреждения за два дня, недельные/месячные дайджесты, автолимиты сохранены.
- Генерация лимитов использует полный период трёх календарных месяцев;
  пустой/ошибочный ответ не затирает пользовательские значения.
- Отметки рассылок на Volume, RLock Sheets, короткий read-cache с invalidation при записи.
- Notes поездки сохраняется в Trips E, а не только возвращается вызывающему коду.

### Отчёты и погода
- /chart сохраняет 6 панелей, подписи категорий читаемы даже при большом перекосе.
- Процент перерасхода настоящий, а не обрезанные «150%».
- PDF 2 A4: переносы текста, легенда вместо слипшихся подписей, нет emoji-квадратов.
- Месяц графиков — Астана, не UTC сервера; названия месяцев на русском.
- Общий lock для Matplotlib; Excel содержит реальные 16 полей плюс долги.
- Погода разбита на блоки, прошедшие часы не выводятся как будущие,
  ветер в км/ч, отсутствие данных не печатается как None%.
- Длинные Telegram-сообщения делятся; ошибки разметки не скрывают сетевой сбой.

## Долги
Отдельный журнал Debts: выдача/получение, частичный/полный возврат, остаток/срок.
Перед записью подтверждение; проверяются сумма, KZT, принадлежность, превышение остатка,
неоднозначные совпадения и повтор события. Старые расходы не переклассифицируются
автоматически в долги. Principal не входит в доходы/расходы.
Проценты отдельно; срок долга автоматически напоминание не создаёт.
Ошибочную подтверждённую строку долга исправляют вручную после резервной копии.

## Остаточные ограничения
Нельзя утверждать, что устранены все возможные дефекты и проверена безотказность.
Реальные права Telegram/Google, ключи, сеть, квоты, модели и build проверяются в Railway.
Одна replica, один Volume; ручные редакторы Sheets не участвуют в lock.
При сбое между отправкой Telegram и отметкой Sheets возможен повтор — exactly-once нет.
Уже потерянная история не восстанавливается, память ограничена 50 сообщениями.
Произвольные города, автоконвертация и бесконечное понимание диалога не добавлялись.
Полный простой в окно погоды/дайджеста может пропустить рассылку.
Маркетплейсы могут менять внешние API/HTML; их live-доступ здесь не проверялся.
